PART 02. Identity and Credential Management in Linux
This activity requires the following resources:

Ubuntu Server 22.04 (NOT UBUNTU DESKTOP)

Objective: To practice the issuance, management, verification, revocation, and auditing of identities and credentials for authorised devices, users, and processes in a Linux environment.

You will need to complete the following activities:

User Account Creation:

Create a new user account named labuser with a home directory.

Set a password for the new user.

SSH Key Pair Generation:

Generate an SSH key pair for labuser.

Configure SSH to allow key-based authentication for labuser.

Password Policy Setup:

Implement a password policy that enforces complex passwords and regular password changes.

Test the password policy by attempting to change the password for labuser.

User Identity Verification:

Verify the identity of labuser using the whoami command.

Display information about the currently logged-in users using the w or who command.

User Credential Revocation:

Temporarily disable the account of labuser using the passwd command.

Attempt to log in as labuser to ensure that access is denied.

Process Identity and Credentials:

Identify the processes running under the labuser account using the ps command.

Review the process credentials using the following commands:

ps -eo user

groups

Audit Logging:

Enable audit logging for user-related events using the auditd service.

Perform actions such as logging in, changing passwords, and revoking access for labuser.

Review the audit logs to identify the recorded events.

Clean-up:

Re-enable the account of labuser.

Remove the SSH key pair for labuser.

Disable audit logging.

TASK 02

User Account Creation:

sudo adduser labuser

Set a password for the new user:

sudo passwd labuser

Generate an SSH key pair for labuser

sudo -u labuser ssh-keygen

Configure SSH to allow key-based authentication

sudo cp /home/labuser/.ssh/id_rsa.pub /home/labuser/.ssh/authorised_keys

sudo chown labuser:labuser /home/labuser/.ssh/authorised_keys

sudo chmod 600 /home/labuser/.ssh/authorised_keys

Password Policy Setup: Install the necessary tools

sudo apt-get install libpam-pwquality

Edit the password policy configuration file

sudo nano /etc/security/pwquality.conf

Add the following lines to pwquality.conf

minclass = 3
minlen = 8

Edit the common-password file to enforce the password policy

sudo nano /etc/pam.d/common-password

Add the following line to common-password

password requisite pam_pwquality.so retry=3

TASK 03

User Identity Verification: Verify the identity of labuser

whoami

Display information about the currently logged-in users

who -u

User Credential Revocation: Temporarily disable the account of labuser

sudo passwd -l labuser

Attempt to log in as labuser (verify access is denied)

su - labuser

TASK 04

Process Identity and Credentials:

Identify processes running under the labuser account

ps aux | grep labuser

Review process credentials

ps -eo user

TASK 05

Audit Logging:

Install auditd

sudo apt-get install auditd

Enable audit logging for user-related events

sudo nano /etc/audit/audit.rules

Add the following line to audit.rules

-w /etc/passwd -p wa -k identity_changes

Restart the auditd service

sudo systemctl restart auditd

Perform actions and review audit logs

sudo su - labuser

sudo passwd labuser  # Change password

sudo passwd -l labuser  # Lock the account

Review the audit logs

sudo ausearch -k identity_changes

TASK 06 (Clean Up)

Re-enable the account of labuser

sudo passwd -u labuser

Remove the SSH key pair for labuser

sudo rm -r /home/labuser/.ssh

Disable audit logging

sudo systemctl stop auditd

Adjustments may be needed based on specific configurations or changes in future Ubuntu versions.

Taskset 01: Cryptographic Hash Functions

Objective: This activity introduces various hash functions available via the Linux command line and provides hands-on experience with generating hash values for files. By the end of this lab, you will be familiar with using hash functions to verify data integrity and generate unique identifiers for files.

Requirements:

A Ubuntu Server 22.04 virtual machine

Start your Ubuntu 22.04 Server and from the terminal, generating a hash (digital fingerprint) from a sequence of alpha-numeric characters.

NOTE: A unique hash (digital fingerprint) can be calculated for a sequence of any characters of an arbitrary length; using a command construct of echo –n your_characters | hash function where:

echo is used to display text or output to the terminal (i.e. when you run the echo command followed by a string or variable, it prints that string or the value of the variable to the standard output (usually the terminal, but can also be to a file).

-n option is used to suppress the trailing newline that is usually appended to the output of the echo command.

your_characters represent the input to be hashed

|: is the pipe operator that takes the standard output produced by the command on its left (echo) and passes it as the standard input to the command on its right (hash_function).

hash function is the choice of cryptographic hash function that will be used to generate the hash (e.g. md5, sha-256, sha384 etc).

1.1) In the terminal type

echo -n cat|sha256sum

In this example, the characters being hashed is the word cat, and the cryptographic hash function used to generate the hash, is sha256. The unique hash for the word cat is:77af778b51abd4a3c51c5ddd97204a9c3ae614ebccb75a606c3b6865aed6744e

​1.2) In the terminal type

echo -n cat|md5sum

In this example, the characters being hashed is the word cat, and the cryptographic hash function used to generate the hash, is md5. The unique hash for the word cat is:d077f244def8a70e5ea758bd8352fcd8

NOTE: Cryptographic hash functions are sensitive to case (i.e., upper, lower); punctuation and spaces etc. Therefore, “cat”, “Cat”, “cat.” and “cat”, will all generate different hashes.

openssl: This is the command-line tool for using the OpenSSL library, which provides cryptographic functions and tools.

rand: This is a subcommand of OpenSSL used for generating random data.

-hex: This option specifies that the output should be in hexadecimal format.

Taskset 04: File Encryption and Decryption

For this taskset you will use gpg (GNU Privacy Guard) to perform file-level encryption.

4.1) Encrypt a file

gpg -c myfile.txt

Understanding this command: gpg: This is the command-line interface for Gnu Privacy Guard, a widely used encryption tool.

-c: This option tells GPG to encrypt the file.

myfile.txt: This is the name of the file you want to encrypt. The specified file (myfile.txt) will be replaced with an encrypted version, and the original file will no longer be accessible without decrypting it.

When you run this command, GPG will prompt you to enter a passphrase or password. This passphrase will be used to encrypt and later decrypt the file.

4.2) Decrypt a file

sudo gpg myfile.txt.gpg

Where myfile.txt.gpg is the name of the encrypted file that you want to decrypt. You will be prompted for a passphrase to decrypt the file.

Taskset 05: Secure File Deletion

For this taskset you will use the shred tool to securely delete a file.

5.1) Type the following command

shred -u myfile.txt

Understanding this command:

The command shred -u myfile.txt does the following:

Overwrites the content of the file myfile.txt with random data multiple times to securely delete its original content, making it more difficult for someone to recover the original data.

After the overwriting process is complete, the -u option ensures that the file is unlinked or removed from the file system.

This command is often used when there is a need to permanently delete sensitive information from a file and ensure that it cannot be easily recovered.

IMPORTANT NOTE: The effectiveness of shred can depend on factors such as the file system and storage medium. In some cases, secure deletion may not be guaranteed due to features like wear leveling in solid-state drives (SSDs).

6.2) Use secure Copy (SCP) between the Kali VM and the Ubuntu Gateway VM. Type:

scp /path/to/local/file user@destination_machine:/path/to/remote/directory

Understanding this command: The scp command is used for secure copy, and it is typically used to copy files or directories between hosts over a secure, encrypted SSH connection.

scp: The command itself, which stands for secure copy.

/path/to/local/file: The path to the local file on the machine where the command is being executed. This is the file that you want to copy.

user@destination_machine: The username (user) and the address (destination_machine) of the remote machine where you want to copy the file.

:/path/to/remote/directory: The destination path on the remote machine where you want to copy the file. It can be a directory or a specific filename.
